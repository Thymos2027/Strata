# Additional mechanism checks (local draft, not posted)

Follow-up to the published isolated af08278c copy-slice validation on 46c152a1. Model, 63 fixed slots, chunk2048, 7 workers, MTP0 and binaries remain unchanged; this does not validate the complete stacked PR.

Reading the original two 16K traces now verifies all 320 staging operations individually: A HtoD bytes equal B HtoD + DtoD at every stage, with exactly 63/256 resident bytes moved by DtoD and 193/256 by HtoD. The two buffer generations alternate 160 times each. Event ID **and eventSyncId**, plus runtime correlation IDs, connect the same prior-reader event to both copy streams, the DtoD completion to the host-copy stream join, and the joined copy event to the compute stream. Every relevant API reports success. Device-side event completion timestamps were zero, so this is enqueue/dependency evidence, not measured device wait duration or a byte dump of staging memory.

Stream metadata records priorities 0/0/-5 for compute13/HtoD14/DtoD15 (the last was stored as uint32 4294967291). DtoD activity totals 208.49 ms, with 193.96 ms overlapping HtoD and only 9.11 ms overlapping compute kernels. This confirms stream assignment and substantial copy/copy overlap; it does not isolate the performance contribution of priority versus segmentation/separate streams or establish hardware preemption.

Separately, elevated 500Hz CPU leaf-IP/context-switch captures on the original baseline at 1K/16K and the isolated on arm at 16K passed output/layout checks, with same-day unprofiled controls. In the baseline 16K decode window, 52.63% of all engine-process periodic samples were in the worker epoch-wait loop, 20.09% in identified arithmetic/quantization functions, and 13.45% were unresolved kernel addresses. Profiler-injected threads remain in the denominator. All 2430 identified arithmetic samples were at GPU-uncovered instants, but neither these samples nor on-CPU overlap is elapsed critical-path time. Combined capture decode/plain ratios were 1.165/1.152/1.104, so these traces do not replace the existing unprofiled paired performance results. Full stacks, job-lifecycle causality and kernel symbolization remain unverified.
