## 可以继续的工作

以下均为待执行项目，不能当作已通过证据。

1. **先建立当前主线基线。** 在独立构建目录编译 `7ddc17a3`，重跑适用门禁和最小 1K 控制；显式固定 `--conversation-cache-mib 0`、worker、专家布局、MTP、上下文、chunk 和采样。HtoD 异常时只做构建与正确性，不填写性能结论。
2. **把旧 #3641 的 16K gate 限定为历史兼容性补充。** 已有 1K/64-token 对照通过，但不能推及长上下文。若需要补齐旧 head 的正确性证据，可使用 `../qwen36-pr3641/run_ab.py --mode gate --case r0-l16384`；结果必须标明固定 head `f3f2136f` / base `011c9e6`，不能称为 v0.2.3.1 候选。面向上游的性能工作应等待作者更新，或在明确归属的本地兼容移植上重新跑完整门禁。
3. **设计 GPU 驻留的 attention 算子对照。** 使用真实 GQA head ratio、FP32 KV 和上下文长度，先初始化并拷入 GPU，再预热、用 CUDA Event 测同一输入的旧路径与 GQA 路径；计时区间排除 HtoD、模型加载和 CPU 专家。旧 head 可以回答算子机制问题；要形成当前发布结论，基线和候选必须来自兼容的当前主线构建。先核对独立 oracle，再做交替顺序与重复测量，记录 GPU 时钟、温度和资源竞争。
4. **离线整理时间线和贡献材料。** 可以完善 GPU 活动区间并集、拷贝重叠、CPU 数学计算与等待循环的区分；形成上游验证报告草稿，明确作者、base/head、通过项和缺项。当前 CPU 试采只代表异常会话，不能补写正常工况的最终瓶颈结论。
