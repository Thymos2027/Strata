# Strata 推理研究计划

更新：2026-11-07。当前阅读入口见[报告索引](README.md)，已完成结果见[研究状态](RESEARCH_STATUS.md)和[成果总结](RESEARCH_OUTCOMES.md)。本文件只决定下一项研究如何选择与验收；旧版阶段方案和当时的优先级保留在[历史计划](archive/INFERENCE_RESEARCH_PLAN_LEGACY_20261107.md)。

## 1. 研究方向与交付目标

研究主题是 **资源受限硬件上的高性能 AI 推理**，以 Strata 为实践场景，服务社区正在遇到的真实问题。本机 Windows 11、i7-12700、RTX 5060 Ti 16GB、128GB DDR4 是主要验证环境。Qwen3.8-Flash-Next、Qwen3.6-35B-A3B、DeepSeek V4.1-Flash 三个已在本机短请求通过的模型家族都是可选研究对象；选题不预先绑定某一个模型、算子或优化手段。

目标是把一个具体问题做成社区可复核的贡献：独立验证已有方案、定位并修复问题、补充缺失硬件的数据，或提交有适用边界的性能改进。每项贡献都要能说明用户影响、实验条件、真实结果和限制；负结果也可以有价值。研究不以 trace 数量、构建成功或提交 PR 本身作为完成标准。

性能改进的完整证据链是：固定源码与模型 → 可重建 workload → 明确候选及作用机制 → 正确性门槛 → 同日、无 profiler 的配对测量 → 范围和限制 → 报告或原讨论中的贡献。功能问题和基准报告按各自所需的复现、验证与数据要求交付，不强行套同一性能矩阵。

这些是各自固定版本的证据，不构成模型优先级。选下一项时，先看**社区是否有具体需求、本机能否复现、现有讨论是否缺我们这类硬件的数据、结果能否改变维护者或用户的决定**。随后估计实验成本与上游重叠，选一个最有把握形成有界交付的问题。Qwen3.6 [PR #3905](https://github.com/Niko1221/Strata/pull/3905) 是已有验证可接续的例子；它没有默认优先权。新 [#5468](https://github.com/Niko1221/Strata/pull/5468)、[#5467](https://github.com/Niko1221/Strata/pull/5467) 等方案也要先核对适用模型和配置，不预设本机收益。

## 3. 选题入口与执行方法

| 模型家族 | 可研究的问题举例 | 现有起点 |
| --- | --- | --- |
| Qwen3.8-Flash-Next | 16GB 显卡下的缓存、上下文、并发、草稿验证及真实客户端体验 | 现有 IQ3_S 和[亲和性结果](tobeo-20261029/flash-next-affinity/README.md)；新版本需独立验证 |
| Qwen3.6-35B-A3B | hybrid prefill/decode、专家搬运、长上下文和候选方案的独立验证 | [复制切片结果](tobeo-20261030/qwen36-copy3905/README.md)及[诊断边界](tobeo-20261101/qwen36-wpr-review/DECISION.md) |
| DeepSeek V4.1-Flash | 大模型的 RAM/VRAM/SSD 分层、启动与连续请求的资源边界 | [Windows 单卡案例](tobeo-20261029/deepseek41-case/REPORT.md)；新版本需独立验证 |

这张表是寻找问题的入口，不是待办清单。可以跨模型研究共性问题，也要区分三个引擎路径和各模型的配置、量化与结果；不要把一条路径的收益直接推广到另两条。实际开展时一次聚焦一个明确问题，完成或按停止条件收尾后再换题。

开跑前在独立日期目录写一页 `experiment-plan.md`，必须回答：

1. **问题与价值**：哪个用户行为受影响？是性能、正确性、资源占用还是可用性问题？上游是否已有处理或正在讨论？
2. **可判定的结果**：什么证据会支持继续、放弃或只报告负结果？性能问题选请求总耗时、TTFT、prefill、decode、吞吐、资源占用等相关指标；profiling 用于解释机制。
3. **最小实验范围**：按问题选模型、输入长度、请求形状和对照组。固定并记录模型文件及 SHA-256、源码/二进制、实际配置、采样、缓存、专家布局和后台负载；不要把原 Qwen3.6 的 1K/16K、MTP 0 矩阵套到所有模型。
4. **正确性门槛**：运行相关现有测试及输出检查；若可能改变浮点结果，事先定义容差与任务验收。涉及工具调用、batch、长上下文或草稿时检查对应路径。
5. **性能与停止条件**：性能声明采用同机同日、无 profiler 的重复对照，保留逐次结果、波动、失败和环境状态。收益不超过噪声、作用路径不在关键路径，或用户问题无法复现时及时收尾，不扩成无限采集。

构建每个受影响的后端；编译与硬件运行分开报告。缺少必要环境时明确列为未验证。每轮结束恢复原服务并核对状态；长时间任务按本仓库 `AGENTS.md` 的后台流程执行。

## 4. 暂不启动的方向

- **迟启动根因追踪**：原版无 profiler 根因未知。仅当有具体单因素改动、可区分的观测指标和停止条件时重开；不为了勾选旧清单继续采 ETW。
- **没有问题定义的 GQA、Flash Attention、MTP、缓存或 CUDA Graph 新实现**：先核对当前上游、用户影响与真实关键路径；大功能或默认变更前按[贡献规则](../CONTRIBUTING.md)讨论范围。旧版阶段设计仅供[历史追溯](archive/INFERENCE_RESEARCH_PLAN_LEGACY_20261107.md)。
- **Unsloth `UD-IQ3_XXS`**：下载按用户要求暂停，未全量校验或运行，不作为当前实验依赖。

## 5. 交付与记录

每次实验保留固定 revision、命令、模型与配置身份、逐次结果和失败项。报告把 Passed、Failed、Not run 分开；静态判断标为未实测。已有方案的验证交回原 issue/PR，说明实现归属。较大功能、重构或默认变更先按[CONTRIBUTING.md](../CONTRIBUTING.md)与维护者商定范围。标准 benchmark 协议仍按[当前文档](../docs/BENCHMARK_PROTOCOL.md)判断，不将本机专项实验自动称为标准结果。原始逐项历史见[执行记录](archive/EXECUTION_LOG.md)。
